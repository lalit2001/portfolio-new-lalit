### 1. Idempotency at the Lambda Handler Level

This is like adding tadka to the entire dal - it covers everything!

```
import os
from dataclasses import dataclass, field
from uuid import uuid4
from aws_lambda_powertools.utilities.idempotency import (
    DynamoDBPersistenceLayer,
    idempotent,
)
from aws_lambda_powertools.utilities.typing import LambdaContext

table = os.getenv("IDEMPOTENCY_TABLE", "")
persistence_layer = DynamoDBPersistenceLayer(table_name=table)

@dataclass
class Payment:
    user_id: str
    product_id: str
    payment_id: str = field(default_factory=lambda: f"{uuid4()}")

class PaymentError(Exception):
    ...

@idempotent(persistence_store=persistence_layer)
def lambda_handler(event: dict, context: LambdaContext):
    try:
        payment: Payment = create_subscription_payment(event)
        return {
            "payment_id": payment.payment_id,
            "message": "success",
            "statusCode": 200,
        }
    except Exception as exc:
        raise PaymentError(f"Error creating payment {str(exc)}")

def create_subscription_payment(event: dict) -> Payment:
    return Payment(**event)
```

### 2. Idempotency at the Function Level

This is like adding idempotency to specific dishes in your thali:

```
import os
from dataclasses import dataclass
from aws_lambda_powertools.utilities.idempotency import (
    DynamoDBPersistenceLayer,
    IdempotencyConfig,
    idempotent_function,
)
from aws_lambda_powertools.utilities.typing import LambdaContext

table = os.getenv("IDEMPOTENCY_TABLE", "")
dynamodb = DynamoDBPersistenceLayer(table_name=table)
config = IdempotencyConfig(event_key_jmespath="order_id")

@dataclass
class OrderItem:
    sku: str
    description: str

@dataclass
class Order:
    item: OrderItem
    order_id: int

@idempotent_function(data_keyword_argument="order", config=config, persistence_store=dynamodb)
def process_order(order: Order):
    return f"processed order {order.order_id}"

def lambda_handler(event: dict, context: LambdaContext):
    config.register_lambda_context(context)
    order_item = OrderItem(sku="fake", description="sample")
    order = Order(item=order_item, order_id=1)
    return process_order(order=order)
```

### 🎬 Lights, Camera, Action!

Let's break down these blockbuster codes like a Bollywood movie:

### For Lambda Handler Level Idempotency:

**The Import** : We bring in our star cast, including idempotent_function for handler-level idempotency.**The Setup** : We create a DynamoDBPersistenceLayer and IdempotencyConfig. It's like setting up the kitchen before cooking.**The Hero (Decorator)** : Our @idempotent decorator is the main hero, protecting the entire handler.**The Handler** : Your Lambda handler, now fully protected by the idempotency shield!**The Helper** : process_order function does the actual work, safely wrapped inside the idempotent handler.

### For Function Level Idempotency:

**The Import** : Similar star cast, but we use idempotent for function-level idempotency.**The Setup** : Same kitchen setup with DynamoDBPersistenceLayer and IdempotencyConfig.**The Handler** : Your Lambda handler calls the idempotent function but isn't idempotent itself.**The Hero (Decorator)** : Our @idempotent_function decorator protects the process_order function specifically.**The Star Function** : process_order is now idempotent, like a perfectly cooked dish every time!

### 💡 Pro Tips (Because You're Smarter than the Average Bear 🐻)

**Choose Wisely** : Use handler-level idempotency for blanket coverage, and function-level for more granular control.**Key Selection** : For handler-level, use a key from the event. For function-level, you can use function arguments.**Error Handling** : Powertools handles most errors, but add your own try-except for custom error handling.**Testing** : Test both success and error scenarios to ensure idempotency works in all cases.

### 🚀 Why These Approaches Rock

### Handler-Level Idempotency:

Simplicity: One decorator to rule them all! Comprehensive: Covers all logic within the handler. Consistency: Ensures the entire Lambda execution is idempotent.

### Function-Level Idempotency:

Granular Control: Apply idempotency only where needed. Reusability: Idempotent functions can be used across multiple handlers. Flexibility: Different idempotency configs for different functions.
